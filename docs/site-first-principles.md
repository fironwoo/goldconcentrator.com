# GoldConcentrator.com First Principles

GoldConcentrator.com is not an equipment catalogue. It is the first technical review of a
mineral-processing project.

## The visitor's real decision

The visitor is deciding whether they can trust a process reviewer to identify project risk before
recommending equipment. Every page must therefore answer these questions in order:

1. Is this route relevant to my ore?
2. Does the reviewer understand the variables that can change the route?
3. Why might each process stage or equipment duty be needed?
4. What cannot be concluded from the current information?
5. What should I send, and what will a human reviewer return?

## Rules that must not be broken

- Ore behavior comes before machine names.
- A mineral name alone never determines a flowsheet.
- An untested route is described as preliminary, likely or indicative, never final.
- Recovery, grade and capacity claims require stated ore and operating conditions.
- Unknown information is a valid answer and becomes a clear data request.
- A case proves relevant experience; it is not a design recommendation for another ore.
- Images must prove equipment, material, installation or delivery. They are not decoration.
- Interaction must reduce uncertainty or preserve project context. Decorative interaction is removed.
- Contact language must describe manual review accurately and must not imply live chat.
- The primary call to action asks for useful project evidence, not an immediate machine quotation.

## Module test

Every important module must contain at least one of the following:

- a project input the visitor can provide;
- an if-then process decision;
- a clear application boundary;
- a practical next action.

If a module does none of these things, it should be removed or reduced.

## Page sequence

Each solution page should follow this decision path:

`ore fit -> main risks -> three-question route check -> preliminary route -> process logic -> equipment duties -> comparable evidence -> human review`

## Performance and interaction budget

- One proof image in the solution hero, one lightweight process diagram and no automatic carousel.
- Native HTML and small client-side JavaScript for route checks and form continuity.
- No fake online indicator, typewriter chat, parallax, looping arrows or universal scroll-in effects.
- All interactive targets are at least 44 by 44 pixels on touch screens.
- Motion respects `prefers-reduced-motion`.

## Final quality test

A useful solution page shows that the reviewer knows what to ask, knows when not to conclude and
knows how to turn missing information into an engineering scope that can be tested and quoted.
